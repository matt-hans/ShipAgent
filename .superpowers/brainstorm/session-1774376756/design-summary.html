Angular Module Federation — Full Design Summary

All 8 sections approved. Review the complete architecture before we write the spec.

1. Nx Workspace

Shell — Host app, layout, Tauri bootstrap
4 Remotes — Chat, Sidebar, Settings, Domain
6 Shared Libs — State, API, SSE, Types, UI, Testing
Unified build, team ownership boundaries

2. NgRx SignalStore

8 Feature Stores — app, conversation, job, data-source, settings, contacts, commands, platforms
Cross-remote — Store signals are the bus
localStorage persistence via effects

3. Hybrid SSE

Shared — Generic SseService (lifecycle, reconnect, parse)
Chat Remote — ConversationSse + JobProgressSse
Cross-remote via store signals

4. Component Mapping

50 React → ~60 Angular (decomposed monoliths)
Key splits — CommandCenter→4, PreviewCard→3, DataSourcePanel→3
Direct port where possible, decompose where beneficial

5. Spartan UI + OKLCH

Spartan — Headless primitives (Button, Dialog, Switch, etc.)
Direct port — OKLCH tokens, custom CSS classes, Tailwind v4
Pixel-identical goal, ng2-pdf-viewer, ngx-markdown

6. API Client

ApiService — 40+ endpoints, HttpClient-based
InjectionToken — Shell provides base URL, remotes consume
Error interceptor, auth header, domain-grouped methods

7. Component-Based Loading

No traditional routing — Shell is layout manager
Remotes expose components, not routes
DomainCardRegistry — dynamic card resolution by event type
Matches current React architecture exactly

8. Testing

Jest + Angular Testing Library per project
Shared testing lib — mocks, fixtures, test hosts
nx affected — only test what changed (CI optimization)
Behavior parity verification against React
